# Фаза 3 - сохранение, пакеты и ZIP

Проверено: 10-10-2026. Версия расширения: **0.3.0**. Фаза технически завершена в описанном ниже объёме; публичного релиза и пользовательской релизной приёмки нет. Требования: R-004-R-009 в [PROJECT_SPEC.md](PROJECT_SPEC.md); дальнейшие действия - в [ROADMAP.md](ROADMAP.md).

## Среда и поставка

Использованы отдельные профили на Windows: Zen **1.23.2b / Gecko 157.0.1**, Chromium **148.0.7778.96**. В Zen звук выключен настройкой `media.volume_scale=0.0` тестового профиля; Chromium запущен с `--mute-audio`. Декодирование в FFmpeg направлено в null output. Аудиодорожки в файлах сохранены. Рабочие профили, настройки подписей и общий звук Windows не менялись.

Инструменты: Node.js 22.18.0, npm 10.9.3, Python 3.13.7, FFmpeg/ffprobe 9.0.2. Сборки содержат 49 файлов для Firefox и 50 для Chromium. Встроенные FFmpeg/WASM и Mediabunny не изменены.

ZIP выполняет локальный `zip.js` **2.20.0**, commit `38508528fe00b094447d9122b7725ab412149e2d`, BSD-3-Clause. Bundle и лицензия закреплены в [PROVENANCE.json](../extension/vendor/zipjs/PROVENANCE.json) и [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). Используется последовательный STORE с `WritableStream`, без Web Workers и дополнительного перекодирования. Код, библиотеки и ZIP не загружаются с удалённого сервера.

## Поведение

- Переключатель «Спрашивать, куда сохранить» применяется к видео, аудио, SRT, ZIP и отдельным Page-Blob путям. По умолчанию используется каталог загрузок браузера. Диалог закрывается пользователем без принудительной повторной загрузки.
- «Выбрать несколько…» показывает варианты текущего материала и фиксирует выбранные параметры кодека при открытии. Отдельные файлы обрабатываются последовательно; ZIP доступен при выборе минимум двух позиций. Одиночные команды сохранены.
- Одновременно выполняется один пакет. Privileged messages и результаты привязаны к проверенному sender, вкладке, документу, package/job и текущему индексу. Другой документ не может продвинуть или дописать чужую позицию.
- Runtime ждёт фактического состояния browser download `complete`, а не только выдачи download ID. Конечный путь, размер и bytes файлов проверены отдельно в QA. Для ZIP отметка «подготовлен» отличается от сохранённого архива. Отмена сохраняет завершённые отдельные файлы; подготовленные ZIP-входы доступны через кнопку восстановления в popup.
- Подготовленные файлы записываются в OPFS и индекс восстановления. Отменённые пакеты требуют ручного сохранения; автоматический flush не вызывает новый диалог. Незавершённая передача и частичный архив очищаются по принадлежности операции. Blob URL живёт до завершения или отмены browser download.

Это очередь **форматов одного материала**. Сквозная загрузка разных материалов плейлиста не добавлена и не считается проверенной этим проходом.

## ZIP и измеренный размер

Оба трёхфайловых Coub ZIP имеют размер **7 041 032 bytes**, три STORE entries и корректный CRC. Они извлечены штатным Windows PowerShell `Expand-Archive`. В Zen SHA каждого извлечённого файла совпал с capture bytes **до упаковки этого же запуска**. В Chromium SHA совпал с файлами независимого запуска той же выбранной очереди и Zen prepared bytes; отдельного capture до упаковки именно Chromium-запуска не было. Хеши целых архивов различаются из-за ZIP metadata и не используются как требование одинакового архива.

Дополнительный контроль в обоих браузерах прошёл через настоящий extension content context: `MendoPackageUI.saveBlob` → chunks по 1 MiB → OPFS → подготовка → STORE ZIP → завершённый browser download. Два диагностических файла по 64 MiB дали **128 MiB payload** и архив **134 218 118 bytes**. Это тестовые binary bytes, а не видео. Имена `Контрольный файл.bin` и `контрольный файл.bin` превратились в разные плоские entries с суффиксом ` (2)`.

После `Expand-Archive` весь извлечённый payload обоих браузеров независимо сравнен с известным повторяемым шаблоном, SHA-256 и CRC. Все bytes совпали; overhead ZIP - 390 bytes. В Zen popup закрывался, исходная вкладка скрывалась во время этого прохода; архив завершился. После завершения в Chromium каталоги передач и частичных архивов пусты.

Для Zen диагностический fixture был добавлен только в отдельный тестовый XPI поверх неизменённых production-файлов. После испытания установлена обычная финальная сборка 0.3.0. В Chromium fixture внедрён в уже существующий isolated context. Fixture, профили и outputs находятся в игнорируемой `.local/qa/phase3/` и не входят в сборки или Git.

Реализованные ограничения: максимум **20 позиций**, **1 GiB** для передаваемого файла и готового ZIP с заголовками; подготовка ZIP резервирует 64 KiB сверх payload. Проверяются доступная OPFS quota, размер chunk, sequence и TTL незавершённой передачи. Недостаток квоты, превышение лимита, traversal, Unicode, коллизии и ошибка посреди упаковки покрыты автоматическими отрицательными проверками. Фактическое заполнение диска до отказа, успешный архив 1 GiB, пиковое потребление памяти и ZIP больше 4 GiB **не измерены**. ZIP64 проверен небольшой принудительной fixture; это не доказательство работы многогигабайтного файла.

## Отмена, принадлежность и восстановление

| Проверка | Наблюдаемый результат |
|---|---|
| Zen, очередь двух файлов, отмена второго Save As | Первый MP4 сохранён, второй MP3 не сохранён; UI сообщает «Пакет отменён. Завершено 1/2». Повторного диалога нет; bytes первого файла не изменились. |
| Zen, отмена SRT Save As | UI «Сохранение отменено»; нового файла, download ID и повторного диалога нет. Ранее сохранённый SRT остался неизменным. |
| Zen, restart processor при ожидающем ZIP Save As, затем Cancel | Два готовых входа пережили перезапуск. Через кнопку восстановления и настоящие диалоги отдельно сохранены MP4 и MP3 с исходными SHA. Это комбинированный сценарий restart + Cancel. |
| Chromium, отмена ожидающего ZIP через кнопку пакета | Native download ID 8 получил `interrupted / USER_CANCELED`, конечного filename нет. Два готовых входа остались для ручного восстановления. Физическое взаимодействие с chooser Chromium не подтверждено: native UI-инструмент не смог выбрать его окно. |
| Chromium, две вкладки | Сообщение второй вкладки в чужой пакет отвергнуто: «Пакет не принадлежит этому документу». Собственный запуск второй вкладки получил «Другой пакет уже выполняется». Владелец и индекс первого не изменились; после отмены lease освобождён. Первый пакет удерживался диагностическим fixture, реальное параллельное получение двух материалов не заявляется. |
| Chromium, Cancel во время Blob transfer | После подтверждённого первого chunk реальный OPFS swap содержал 1 MiB. Диагностический harness задержал следующий шаг до нажатия кнопки Cancel. UI «Пакет отменён. Завершено 0/2»; второй Blob не открывался, finish не отправлялся, нового download нет, spool/archives пусты и lease освобождён. |
| Chromium, reload расширения и ручное восстановление | Два готовых файла сохранились в индексе; кнопка popup создала downloads 10 и 11 со статусом `complete`. Реальные MP4/MP3 побайтно совпали с подготовленными входами; у обеих записей появился `savedAt`. Последующий automatic flush: `saved: 0`, `pending: 0`. |

Незавершённые manual-only записи не удаляются по возрасту. В regression tests проверены сохранение записи старше семи дней, отмена очереди восстановления, запись `savedAt` после каждого файла, concurrent additions и ошибка bookkeeping после уже успешного native download. OPFS служит временным хранилищем, а не внешним постоянным архивом: удаление данных расширения или тестового профиля может удалить подготовленные файлы. Автоматическое продолжение активного media job после закрытия всего браузера не проверено и не заявляется.

## Интерфейс и клавиатура

Реальные скриншоты просмотрены: picker Zen при viewport **1230×975** и **360×855**, отменённый ZIP Chromium при **1249×1269** и **360×800**. Диалоги помещаются по ширине; на узком viewport кнопки располагаются вертикально и длинные подписи переносятся. В Zen Space/Tab выбирали два checkbox и включали ZIP; Escape закрывал неработающий picker. Размеры относятся к фактическому content viewport, а не положению окна на мониторе.

Popup настроек отдельно просмотрен целиком при viewport **1190×975** и **306×975**, без горизонтального overflow. Настоящий click по checkbox включил Save As и сохранил `true` в настройках; Space на нём выключил опцию и сохранил `false`. Перед окончанием QA оба профиля оставлены с выключенным Save As.

Новый [скриншот настроек](images/settings-zen-030.png) показывает обычную финальную версию 0.3.0 в Zen: viewport 306×925, capture документа body 306×502. На нём нет пользовательских путей, chooser или приватной информации. Пользовательская визуальная приёмка остаётся отдельной.

## Regression checks и review

Итог: **266/266 tests**. ESLint: **0 errors / 14 warnings** существующего кода. Проверены обе сборки и inventories; outgoing scanner не обнаружил секретов или приватных путей в проверяемом содержимом. Mozilla `web-ext`: **0 errors / 3 vendor warnings** - два прежних FFmpeg warnings и dynamic import в zip.js bundle. ZIP-путь использует локальную библиотеку с отключёнными workers; strict lint с `--warnings-as-errors` не проходит. Полный security scan запланирован перед публичным выпуском.

Тесты покрывают store/CRC/ZIP64, безопасные имена, счётчик квоты, sender и текущий индекс, очередь/ошибку/отмену, Blob lifetime, orphan cleanup, native cancellation, захват актуальных codec settings и recovery. При реальном 128 MiB проходе Zen обнаружен protected `constructor` lookup у foreign buffer view: до первого chunk передача прерывалась. Создана собственная копия bytes перед `subarray`; meaningful regression сначала воспроизвёл сбой, затем прошёл. После исправления реальный Zen ZIP завершился и прошёл byte comparison.

Совокупный внутренний code review и focused review коррекций выполнены. Исправлены подтверждённые ошибки принадлежности текущей позиции, recovery bookkeeping, повторного fallback после Cancel, stale codec selection и очистки потерянных передач. Review не заменяет перечисленные реальные проверки. GitHub PR/review и окончательные SHAs фиксируются в метаданных интеграции; это отдельная проверка от browser QA.
