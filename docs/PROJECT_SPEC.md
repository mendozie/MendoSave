## Результат и объём

MendoSave - самостоятельное расширение для локального сохранения видео, аудио и субтитров. Основная целевая среда - Zen Browser на Windows. Пользователь сохраняет один вариант либо выбирает несколько файлов одного материала и получает их отдельно или в ZIP.

Основой служит Nova Video Saver 1.9, закреплённый commit `6a2bc6dc1234a3c4b0037885b08cad486abe1bac`. Сохраняются существующие возможности YouTube, YouTube Music, Shorts, Rutube, Twitch, VK Видео, TikTok, Coub и Звук по мере проверки их адаптеров. Поддержка каждой возможности подтверждается отдельно; присутствие кода не считается проверкой работоспособности.

Другие ОС и Firefox-производные - последующее расширение совместимости. Instagram Reels - отдельное исследование после основного переноса; его поддержка пока не обещана. Сервис обработки медиа, отдельная программа, Native Messaging, DRM bypass, изменение прав доступа к контенту и платёжные функции не входят в принятый объём. Существующий код Musify отключён и не считается поддерживаемым адаптером.

## Требуемое поведение

- **R-001 - Самостоятельный продукт.** Пользователь видит название MendoSave и его оформление. Ссылки на Telegram, донаты, каналы обновления и релизы автора upstream убираются из рабочего интерфейса и механизма обновления. Происхождение и обязательные лицензии сохраняются в служебных документах; исторические материалы не переписываются.
- **R-002 - Zen/Windows.** Расширение устанавливается в отдельный профиль Zen, получает форматы на поддерживаемой странице, обрабатывает и сохраняет файлы. Продолжительная обработка не зависит от открытого popup. Обработка завершения, закрытия страницы и перезапуска фонового контекста имеет явный результат. Проверенный диапазон браузерных версий записывается по фактическим испытаниям.
- **R-003 - Chromium.** Общие адаптеры и медиалогика используются в Firefox- и Chromium-сборках. Новый перенос не удаляет Chromium-версию. Совместимость общих изменений проверяется на обеих сборках; ограничения каждой сборки описываются отдельно.
- **R-004 - Место сохранения.** По умолчанию файл поступает в стандартный каталог загрузок браузера, обычно Downloads. Опция «Спрашивать, куда сохранить» открывает штатный диалог выбора имени и места сохранения. Настройка применяется к видео, аудио, субтитрам и ZIP, включая адаптеры с отдельным Blob-путём. Отмена диалога считается действием пользователя и не запускает автоматическую повторную попытку сохранения.
- **R-005 - Выбор нескольких вариантов.** В меню можно выбрать несколько имеющихся вариантов: качества видео, аудиоформаты и файлы субтитров. Одна выбранная позиция сохраняется обычным способом. Несколько позиций образуют пакет с явно перечисленными файлами и параметрами. Недоступные варианты не показываются как доступные. Старое одиночное скачивание остаётся удобным.
- **R-006 - Очередь.** Выбранные файлы обрабатываются последовательно, с отдельным состоянием каждого и общим прогрессом. Видны текущий файл, успешные результаты и ошибки. Отмена останавливает текущую работу и следующие позиции, сохраняя уже завершённые файлы. Данные разных вкладок и jobs не смешиваются. Очередь форматов одного материала и существующая очередь разных материалов плейлиста различаются.
- **R-007 - ZIP.** При нескольких выбранных позициях доступен режим ZIP. В архив попадают выбранные файлы с теми же bytes, которые получились после выбранной медиаобработки. Упаковка не вызывает дополнительного перекодирования или снижения разрешения/битрейта. MP3 и другие исходно выбранные преобразования выполняются как часть получения соответствующего файла. Для MP4, аудио и прочих уже сжатых медиа предпочтителен ZIP STORE. Один ZIP требует одного диалога сохранения при включённом R-004.
- **R-008 - Честные параметры результата.** Разрешение, кодек, битрейт, дорожки и длительность соответствуют фактическому результату. Если выбранный вариант недоступен, пользователь получает явную информацию; более низкое качество не выдаётся за выбранное. Архив не маскирует неполный пакет под успешную загрузку всех файлов. SRT сохраняет фактические таймкоды выбранной версии transcript, без смешивания параллельных modern/legacy rows и искусственного продления коротких реплик.
- **R-009 - Ошибки и сохранность.** Неудачная загрузка не выдаёт обрезанный файл за полный. Имена нормализуются без directory traversal; коллизия не приводит к молчаливой перезаписи. При недостатке памяти/диска, отказе API, истёкшей ссылке и ошибке обработки виден понятный результат. Temporary storage и Blob URLs освобождаются по принадлежности job и после завершения соответствующей операции. Восстановление готовых файлов не дублирует и не теряет результат.
- **R-010 - Локальность и приватность.** Медиаданными занимаются браузер и встроенные библиотеки. Серверы автора/форка не получают видео, cookies, токены, историю или журналы. Сеть используется для необходимых запросов к выбранной площадке и её CDN; это отличается от работы без интернета. Обновление самого расширения относится к согласованному каналу распространения. Диагностика локальная, с ограниченным хранением и исключением секретов и подписанных URL из экспортируемого текста.
- **R-011 - Публичный выпуск.** Пользователь получает проверяемый пакет, инструкции по установке, список реально проверенных возможностей и ограничений, описание приватности и сохранённые лицензии. Состав поставки и версии встроенных компонентов воспроизводимы. Исходный архив репозитория, рабочий профиль, приватные данные и legacy CI не входят в релиз автоматически.

## Принятый подход

Остаёмся на JavaScript и WebExtensions, используем существующие адаптеры и встроенные FFmpeg/WASM и Mediabunny. Общая логика получения и обработки отделяется от браузерных различий небольшими интерфейсами. Для двух сборок нужны соответствующие manifest и упаковка; framework rewrite на старте не требуется.

Для candidate сохраняется нынешнее FFmpeg-ядро. Его файлы, версии, лицензии и источники закреплены в [DEPENDENCIES.md](DEPENDENCIES.md). Новая сборка ядра и создание дополнительной среды не выбраны. Воспроизводимость упаковки расширения проверяется отдельно от компиляции сторонних библиотек.

Обработчик ограничивает входы дорожек, удерживаемые в RAM: до 750 000 000 bytes на дорожку и 1 500 000 000 bytes суммарно, включая принятые staging bytes, worker inputs и video prefix. Это защитные пределы, а не измеренная доступная память. Промежуточный приём дорожек прекращается через 20 минут от открытия; новые chunks не продлевают срок. Потоковое muxed video сохраняет отдельный OPFS-путь. Переполнение освобождает текущее задание и возвращает ошибку.

Локальные guards Mediabunny ограничивают материализованные MP4 metadata: до 1 000 000 presentation timestamps, samples одного удерживаемого fragment суммарно по tracks/runs и развёрнутых PCM chunks. Compact PCM samples всего материала этим пределом не ограничиваются. Индексы PCM chunks проверяются по фактическим offsets, `stz2` принимает только ширину 4/8/16, composition offsets вне фактической таблицы пропускаются без пустого многократного цикла. AAC ADTS frame не может быть короче своего header: 7 bytes без CRC, 9 с CRC. Повреждённый или превышающий предел вход получает ошибку; изменённые MPL-исходники входят в поставку.

Входящие записи диагностики имеют строковые поля: tag до 128 символов, text до 65 536. Хранятся последние 400 записей с text до 4 000 символов; ожидающих записей не больше 32. Переполнение диагностической очереди отклоняется и не создаёт бесконечную цепочку операций storage. Экспорт по-прежнему исключает секреты и подписанные URL.

Firefox использует background scripts/event page вместо Chromium service worker. В фазе 1 выбран Firefox host в отдельной неактивной закреплённой вкладке расширения; Chromium сохраняет offscreen document. Общий обработчик и bundled workers используются в обеих сборках. Host подтверждён для Zen 1.23.1b на Windows: обработка продолжается при скрытой или закрытой вкладке инициатора и закрытом документе popup. Закрытие самого host прерывает работу; следующая загрузка создаёт новый. Автоматический resume текущего задания не реализован. В фазе 4 полный restart Chromium подтвердил прекращение активного job без неполного output и сохранение трёх готовых inputs для ручной выгрузки; полный restart Zen требует постоянной установки. Evidence и границы находятся в [PHASE1_VERIFICATION.md](PHASE1_VERIFICATION.md) и [PHASE4_VERIFICATION.md](PHASE4_VERIFICATION.md).

Для Twitch live MediaRecorder остаётся у плеера, а полученные chunks последовательно записываются в OPFS обработчика. Port связывает запись с исходной вкладкой и документом. При reload или закрытии страницы обработчик завершает полученный фрагмент и помечает его `[частичная запись]`; финальные события уничтоженного документа для этого не требуются. WebM собирается локальным Mediabunny без перекодирования. Перед чтением пакетов обработчик сохраняет полные EBML blocks усечённого хвоста, независимо сверяет число пакетов и проверяет готовый файл. Неполный хвост также вызывает пометку частичной записи. Это сохранение уже полученных данных при закрытии источника, а не resume после закрытия host или браузера. Проверки и пределы находятся в [PHASE2_VERIFICATION.md](PHASE2_VERIFICATION.md).

Запись выбирает поддерживаемый VP9/Opus или VP8/Opus; при их отсутствии возвращает ошибку до начала job. Отсутствие captured audio допустимо: состав определяется контейнером, а не codec preference MIME. При stall сборки ошибка возвращается с ограниченным ожиданием cleanup; исходник сохраняется, а failed output удаляется после освобождения writer. Бесконечное ожидание native cancellation не должно удерживать finalization.

Длительная обработка, OPFS, WASM workers, WebCodecs и конечная передача Blob в downloads проверяются в Zen. Кодеки выбираются по реальным capabilities. Отсутствие нужного hardware encoder приводит к явному проверенному fallback, а не обещанию той же скорости.

Обычный Firefox WebExtension может открыть диалог сохранения файла, но не назначить произвольный абсолютный путь через `downloads.filename` или сохранить handle любой внешней директории через `showDirectoryPicker`. Поэтому R-004 реализуется штатным Save As. Отдельный файл в очереди может требовать собственного диалога; ZIP объединяет несколько результатов в один. Установка программы ради постоянной внешней папки не входит в принятый подход. Ограничения подтверждены [downloads API](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/downloads/download) и [данными совместимости Mozilla](https://github.com/mdn/browser-compat-data/blob/main/api/Window.json).

Для очереди и ZIP реализована последовательная обработка с готовыми входами и временным архивом в OPFS. Локальная `zip.js` 2.20.0 (BSD-3-Clause) записывает STORE через `WritableStream`, без workers и повторного перекодирования. Пакет ограничен 20 позициями; файл передачи и итоговый ZIP - 1 GiB, с дополнительным резервом 64 KiB при подготовке. Реально проверены 128 MiB в обоих браузерах и payload 1 GiB минус 64 KiB в Chromium с полным извлечением и byte comparison. Верхняя граница Zen и фактическое заполнение квоты не проверены. ZIP64 покрыт малой принудительной fixture, файлы больше 4 GiB не обещаются.

На обработчик приходится один активный пакет, принадлежащий вкладке и документу. Для каждой позиции проверяется текущий индекс и принадлежность job. Завершённые отдельные файлы остаются при отмене. Готовые входы отменённого ZIP сохраняются в OPFS и выдаются через ручную кнопку восстановления; автоматический flush не повторяет отменённое сохранение. Записи manual-only не удаляются по возрасту. Это temporary storage: очистка данных расширения может удалить ещё не выгруженные файлы, а восстановление активного незавершённого media job не заявляется.

Оформление строится вокруг существующего компактного меню с группами видео, аудио и субтитров. Полный визуальный redesign не согласован. Способ выбора нескольких позиций должен работать с клавиатурой и не терять состояние при обычном взаимодействии с меню.

## Проверка и приёмка

| Критерий | Условие и наблюдаемый результат |
|---|---|
| A-001 | Пакет загружается в отдельный профиль Zen/Windows; popup, content scripts, processor и worker взаимодействуют без ошибки неподдерживаемого API. Записаны точные версии браузера и пакета. |
| A-002 | На контрольном видео сохраняются видео, отдельное аудио и субтитры. Проверены контейнер, дорожки, параметры, длительность и начало/конец. Отдельно проверены прямой путь и обработка через медиапроцессор. |
| A-003 | При включённом выборе места появляются штатные диалоги для видео, аудио, субтитров и ZIP; файл действительно находится в выбранном месте. При отмене нет принудительного сохранения или повторного диалога. |
| A-004 | При нескольких выбранных вариантах очередь получает ровно выбранные файлы. Повторный запуск, ошибка и отмена дают явные состояния; job другой вкладки не может изменить текущую. |
| A-005 | ZIP читается стандартным архиватором Windows. Состав соответствует выбранным позициям; хеши извлечённых файлов совпадают с файлами до упаковки. Проверены одинаковые имена, Unicode, traversal, частичная ошибка и нехватка ресурсов. |
| A-006 | Долгая обработка, скрытая вкладка, закрытый popup, навигация, завершение/перезапуск processor и восстановление не дают молчаливой потери или дубликатов. Большой файл проверен отдельно; границы размера указаны по измерениям. |
| A-007 | Для каждого заявленного сайта есть реальные проверенные сценарии на Zen. Chromium regression покрывает общую изменённую логику. Непроверенные сценарии названы непроверенными. |
| A-008 | Проверены схемы и источники сообщений, принадлежность jobs, URL/redirect policies, объёмы и имена. Страница не получает секреты расширения или произвольный доступ к downloads/storage. Проверены журналы и реальный сетевой трафик. |
| A-009 | Меню проверено при широком и узком viewport; сохранены размеры и скриншоты. Выборы, отмена, прогресс, keyboard focus и одиночная загрузка работают. |
| A-010 | Перед выпуском пройдены применимые unit/integration checks, `web-ext` lint/build, code review и репозиторный security scan; существенные findings устранены либо явно разобраны до выпуска. Пакет содержит лицензии и необходимые notices, а приватные материалы исключены. |

Для известных изменений поведения применяется TDD. Автоматические проверки не заменяют реальную проверку расширения и конечных файлов в Zen. Syntax-only, mocked API probe и сходство браузерных движков не считаются A-001/A-002. Chromium и Firefox имеют отдельные evidence.

Для постоянной установки выбран подписанный unlisted XPI с ID `mendosave@mendozie`; подписание прямо разрешено 10-10-2026. Публичный AMO listing сейчас не планируется, репозиторий остаётся приватным, обновления устанавливаются вручную. Подпись и установка проверяются отдельно от технической подготовки. Требования Mozilla проверены по [официальному описанию](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/); принятие пакета Mozilla пока не подтверждено.

Taste skill для визуального redesign не выбран; если появится отдельное поручение на redesign, его выбор согласуется тогда.

## Отложенные решения

- Автоматическое восстановление незавершённого задания и полный browser restart - последующие проверки; host первого среза выбран выше.
- Верхний измеренный размер ZIP, фактический отказ квоты и длительный media job - дополнительные испытания перед релизом; текущие ограничения и evidence указаны выше.
- Канал распространения, стабильный add-on ID, собственные обновления и минимальные проверенные версии - перед публичным релизом.
- Instagram Reels и другие ОС - после основной совместимости, по отдельному решению.
